# ニュースレター配信管理アプリ（MVP）

1年間有料ニュースレター／メールマガジンを配信するためのアプリです。
「その日に書いた記事を、契約期間内の会員だけに配信する」仕組みで、365通を先に準備するステップメールではありません。

このドキュメントは、プログラミングに詳しくない方でもセットアップできるよう、
「○○を開いてください」「ここに入力してください」のレベルで書いています。

---

## 1. 全体の仕組み（先に読んでください）

- **データベース**：Supabase（無料枠あり）に、会員情報・契約期間・ニュースレター・送信履歴を保存します。
- **アプリ本体**：Vercel（無料枠あり）に、この `newsletter-app` フォルダをそのまま公開します。
- **メール送信**：最初はResend（無料枠あり）を使います。
- **契約期間の判定**：会員ごとの「契約開始日」「契約終了日」から、送信のたびに自動判定します。手作業は不要です。

---

## 2. 事前準備（アカウント作成）

以下の3つのサービスに、無料でアカウント登録してください（すべてメールアドレスでOKです）。

1. **Supabase**：https://supabase.com/ → 「Start your project」からサインアップ
2. **Vercel**：https://vercel.com/ → GitHubアカウントでサインアップ（推奨）
3. **Resend**：https://resend.com/ → サインアップ

---

## 3. Supabase（データベース）のセットアップ

1. Supabaseにログインし、「New project」を押してプロジェクトを作成します（リージョンは `Northeast Asia (Tokyo)` がおすすめです）。
2. プロジェクトが作成できたら、左メニューの **SQL Editor** を開きます。
3. このリポジトリの `newsletter-app/supabase/migrations/0001_init.sql` ファイルを開き、中身をすべてコピーします。
4. SQL Editorに貼り付けて、右下の **Run** ボタンを押します。「Success」と表示されればOKです。
5. 左メニューの **Project Settings > API** を開きます。
   - `Project URL` をコピーしておきます（後で使います）
   - `service_role` の下にある `secret` キーをコピーしておきます（**他人に絶対に見せないでください**）

---

## 4. Resend（メール送信）のセットアップ

1. Resendにログインし、左メニューの **API Keys** から新しいキーを作成し、コピーしておきます（`re_` から始まる文字列）。
2. 本番でメールを送るには、送信元ドメインの認証が必要です。左メニューの **Domains** から、あなたの持っているドメインを追加し、案内に従ってDNS設定を行ってください。
   - ドメインをまだお持ちでない場合は、最初はResendのテスト用アドレス（`onboarding@resend.dev`）で動作確認だけ行い、本番配信前にドメインを用意してください。

---

## 5. アプリの環境変数を設定する

1. `newsletter-app` フォルダの中にある `.env.example` というファイルをコピーして、同じ場所に `.env.local` という名前で保存します。
2. `.env.local` を開き、以下を埋めます。

| 変数名 | 内容 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 手順3でコピーした `Project URL` |
| `SUPABASE_SERVICE_ROLE_KEY` | 手順3でコピーした `service_role secret` |
| `ADMIN_EMAIL` | あなたが管理画面にログインするためのメールアドレス（好きなもので構いません） |
| `ADMIN_PASSWORD` | あなたが管理画面にログインするためのパスワード（推測されにくいものにしてください） |
| `ADMIN_SESSION_SECRET` | ランダムな長い文字列。ターミナルで `openssl rand -hex 32` を実行すると作れます |
| `RESEND_API_KEY` | 手順4でコピーしたAPIキー |
| `MAIL_FROM` | 送信元メールアドレス。例: `あなたの名前 <you@yourdomain.com>` |
| `NEXT_PUBLIC_APP_URL` | 公開後のアプリのURL（後述のVercelデプロイ後にわかります。最初は仮でOK） |
| `CRON_SECRET` | 予約送信の自動実行を保護する合言葉。ランダムな文字列でOK |

---

## 6. Vercelに公開する

1. このリポジトリをGitHubに置いた状態で、Vercelの管理画面から **Add New > Project** を選び、このリポジトリを選択します。
2. **Root Directory** の設定で `newsletter-app` を指定してください（リポジトリ直下ではなく、このフォルダがアプリの場所です）。
3. **Environment Variables** の画面で、手順5で `.env.local` に書いたものをひとつずつ登録します。
4. **Deploy** を押します。数分で公開されます。
5. 公開されたURL（例: `https://xxxx.vercel.app`）をコピーし、Vercelの環境変数の `NEXT_PUBLIC_APP_URL` を実際のURLに更新して、再度デプロイしてください（**Deployments** タブの「Redeploy」で構いません）。

---

## 7. 予約送信の自動実行（Cron）を設定する

予約送信された記事は、`api/cron/send-scheduled` というURLが定期的に呼ばれることで自動送信されます。

- Vercelの無料プラン（Hobby）は、1日に複数回実行されるCron設定があると**デプロイそのものがブロックされる**ため、`vercel.json` には保険として「1日1回」の実行だけを設定しています。
- 予約送信を実際に使うには、外部の無料サービス（例: [cron-job.org](https://cron-job.org/)）に登録し、以下のURLを1分〜5分おきに呼び出すよう設定してください。これが実質的な自動送信の仕組みになります。

```
https://あなたのアプリのURL/api/cron/send-scheduled
```

このとき、リクエストヘッダーに以下を付けてください（`.env.local`の`CRON_SECRET`と同じ値にします）。

```
Authorization: Bearer あなたのCRON_SECRET
```

（Vercel純正のCronを使う場合は、`CRON_SECRET`環境変数さえ設定していれば、Vercelが自動的にこのヘッダーを付けて呼び出してくれます。）

## 8. 使い方

### 8-1. ログイン
公開したURLにアクセスすると、ログイン画面が出ます。手順5で決めた `ADMIN_EMAIL` / `ADMIN_PASSWORD` でログインしてください。

### 8-2. 会員を登録する
- 「会員一覧」→「会員を登録する」から、名前・メールアドレス・商品名・決済方法などを入力します。
- 「支払い済みの場合、今すぐ契約を開始する」にチェックを入れ、決済状況を「支払い済み」にすると、契約開始日から自動で契約終了日（1年後）が計算されます。
- お客様自身に申し込んでもらいたい場合は、`/apply` ページ（例: `https://あなたのアプリのURL/apply`）を案内してください。この場合は「申込のみ（支払い未確認）」で登録され、入金確認後にあなたが会員詳細画面から「支払いを確認して契約開始」を押すと契約が始まります。

### 8-3. 今日のニュースレターを書いて送る
1. 「ニュースレター」→「新しいニュースレターを書く」を開きます。
2. タイトル・件名・本文を入力します。本文の入力欄の上にある「画像を挿入」「リンクを挿入」「ボタンを挿入」ボタンを押すと、URLを聞かれるので入力するだけでHTMLメールの部品が挿入されます。
3. 「下書きとして保存する」を押すと、編集画面に移動します。
4. 「プレビューを見る」でPC表示・スマホ表示を確認できます。
5. 「自分だけにテスト送信」を押すと、あなた（`ADMIN_EMAIL`）宛にだけ届きます。会員には届きません。
6. 内容に問題なければ、
   - すぐ送りたい場合は「今すぐ送信」（確認ダイアログが出ます）
   - 予約したい場合は「送信予定日時」を入れて「この日時に予約する」

送信対象は、その時点で契約が有効な会員だけです。手作業での選別は不要です。

### 8-4. 会員の管理
会員一覧・会員詳細画面から、以下ができます。
- 「1年間更新する」：契約終了日の翌日から、新たに1年間の契約を作ります（更新回数・契約履歴も記録されます）
- 「配信を停止する／再開する」：契約期間中でも一時的に配信を止められます
- 「解約する」：以後配信されません（データは削除されません）
- 「配信停止にする」：会員本人がメール内の配信停止リンクを押した場合と同じ状態にできます

## 9. 今後の拡張（このMVPには含まれていません）

- **Stripe連携**：`src/lib/members.ts` の `renewMember` / `confirmPaymentAndStart` を、Stripeの決済完了Webhookから呼び出すようにすれば、自動更新に対応できます。
- **他のメール配信サービスへの切り替え**：`src/lib/email/` フォルダに新しいプロバイダー（Brevo, SendGrid, SESなど）を追加し、`EMAIL_PROVIDER` 環境変数で切り替えられる設計にしてあります。
- **期限が近い会員への自動リマインドメール**：会員一覧の「期限が近い人」フィルタ（30/14/7/1日前）は実装済みです。自動メール送信は今後の拡張予定です。

## 10. 開発者向けメモ

```bash
cd newsletter-app
npm install
npm run dev       # ローカルで起動 (http://localhost:3000)
npm run build     # 本番ビルド
npm run typecheck # 型チェック
```

- 会員の「有効／期限間近／期限切れ」等の状態は、`member_view` というデータベースのビュー（`supabase/migrations/0001_init.sql`）で、保存された値ではなく常に日付からその場で計算しています。バッチ処理の更新忘れによる事故を防ぐためです。
- 二重送信防止は、(1) ニュースレターの状態を `draft/scheduled/failed → sending` に条件付きで切り替える処理、(2) `newsletter_sends` テーブルの `(newsletter_id, member_id)` 一意制約、の二重の仕組みで担保しています。
- 依存パッケージに関する `npm audit` の指摘（PostCSSのビルド時ツールに関するもの）は、外部から送られてくるCSSを処理する使い方をしていないため実害はありませんが、定期的に `npm outdated` / `npm audit` を確認し、更新を心がけてください。
